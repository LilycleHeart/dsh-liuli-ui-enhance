# 官方 DeepSeek Harness Desktop 0.1.7-rc.2 适配

本分支以官方 `@deepseek-ai/dsh-desktop` 0.1.7-rc.2 为目标，保留原 `beta` 分支供社区 DSH Desktop 2.0.13 使用。插件包版本为 `0.1.2-rc.25`，只声明与 dsh 0.1.7-rc.2 兼容。

## 接口迁移

- 会话列表不再携带 `current`。琉璃从 `retainedBy.mainView` 识别主视图会话，并通过 `uiWorkspace.openSession()` 导航。
- 后台作业由 Job Controller 提供；开发者工具面板订阅其会话作业流。完成提醒由 `uiSession.sessionStatus` 提供。
- 根布局使用 `main` 和 `rightbar` 槽位；PTC 子调用使用 `tool/ptc-dispatch-*` 事件。
- 官方 0.1.7 将会话页头改为根作用域 `conversation.header`；独立页头面板按新槽位搬移真实 `<header>`，避免顶部空卡片和正文内重复页头。
- 图标名称、代码块文案和 dockkit 依赖已更新到 0.1.7-rc.2。琉璃禁用 dockkit 装饰性标签滚动渐隐的补丁保留在新版包上。

## 官方桌面壳边界

旧版的无边框补丁只允许在应用包名为 `dsh-plugin-desktop` 的社区客户端上运行。官方桌面端包名为 `@deepseek-ai/dsh-desktop`；插件在其 Host 中不会修改 `app.asar` 或执行补丁还原。

默认保留官方标题栏。需要琉璃悬浮按钮时，可显式运行独立的 Windows 官方壳补丁；它只支持 0.1.7-rc.2，不会由插件自动执行。

```powershell
node scripts/patch-official-window-controls.mjs --check
# 完全退出官方桌面端后应用，再启动桌面端
node scripts/patch-official-window-controls.mjs --apply
# 完全退出后恢复原壳
node scripts/patch-official-window-controls.mjs --revert
```

补丁备份安装目录内的 EXE 和 app.asar 到 `liuli-window-controls-backup-0.1.7-rc.2`。它修改主窗口为无边框、增加四项窗口动作的 IPC 白名单，沿用官方发送者校验，并同步 ASAR 哈希；修改后的 EXE 不再匹配厂商原签名。应用升级会覆盖补丁，新版本必须重新适配，不能直接套用。还原时检查文件哈希，拒绝覆盖已升级的应用。

插件识别官方桥接后启用右上角悬浮胶囊：平时隐藏，移入右上角显示。左上角应用与编辑菜单收进悬浮胶囊，顶部短提示条支持悬停、点击或键盘聚焦展开，不再占据标题栏或 dock 布局高度。侧栏开关和新建会话恢复面板内定位，随侧栏移动；窄轨图标避开 dock 抓手。应用窗口拖动由胶囊抓手提供，不将 dock 标签改成窗口拖动区。插件未加载时，预加载脚本提供常驻窗口按钮兜底。

## 构建与验证

在本分支运行 `pnpm install`、`pnpm run build`，再以 `pnpm pack` 生成本地安装包。安装到官方端后，检查插件行状态、设置页、会话与右栏、壁纸和主题切换，并重启确认持久化。测试前备份 profile；若启动失败，可从官方恢复对话框停用第三方插件，再恢复旧包。

rc.11 曾在官方桌面端实测悬浮唤出、隐藏、最大化、向下还原及最小化后恢复，也核对了原生应用菜单弹出、侧栏开合、浮动侧栏和右侧停靠。rc.2 移除 attachPanels 后，侧栏公共动作在琉璃 dock 挂载期间重定向至其布局状态，卸载时恢复原动作。rc.4 已确认顶部空白页头消失，标题与声纹在同一页头卡片中显示。此后的改动见下方逐版记录。

## rc.11 桌面交互与统一右栏

- 功能设置新增“左上角应用菜单”：悬浮提示条 / 常驻侧栏胶囊。常驻入口跟随侧栏 Logo 行，侧栏不存在时回退到窗口角落；设置保存后即时应用。
- “触顶卡片拖窗高度”范围 0–40px，默认 24px，0 关闭。实测卡片触顶范围内减去按钮、输入框、标签、分隔手柄等交互区域后才生成 Electron 拖动片段；窗口边缘保留缩放空间。可见菜单、模态和指针拖动期间暂停。
- 设置模态中的 portal 菜单层级高于设置遮罩，保留官方菜单键盘交互。
- 官方 Windows 端直接渲染官方 rightbar，并通过官方 tab 注册表接入琉璃面板，移除包装整个官方栏的第二层标签。原生文件预览保留原来的 Tab 域与资源生命周期。琉璃标题槽补齐文字。
- 右栏内部使用官方标签、左右分栏与浮窗能力；外层整个侧栏仍参加琉璃全局 dock 拆分和移动。社区客户端继续原有的内部四向 dock 路径。
- 官方布局公共 openRightbar/closeRightbar 动作在琉璃 dock 挂载期间同步到实际占宽状态，卸载恢复。
- 实际窗口已验证设置菜单可见且能选择常驻模式，重启后常驻入口保留；开发者工具与官方 PDF 预览同栏。历史 PDF 本身已不存在，其原生“文件不存在”提示与本次标签布局无关。
拖窗区域最后一次复测被用户同时操作中断；rc.11 已修正隐藏浮层误阻断与整页焦点容器误避让，但实际拖窗结果尚未完成最终验收。

## rc.14 验收修正

- 常驻模式现在直接将官方“应用 / 编辑”菜单放在侧栏顶部；无二级胶囊入口，收起态纵向排列。修复菜单位置覆盖的 CSS 优先级。
- Dockable 模式在会话 header 常驻左右侧栏开关，隐藏侧栏内部的重复开关与官方分栏按钮；已实测收起两栏后 header 展开按钮仍在。
- 功能设置提供 sidebar_layout_mode：dockable / official，保存后等待设置同步并刷新界面。官方模式保留原生右栏，Dockable 模式增强同一个原生 Tab 域的四向落区与跨区投放。
- official-dock-enhancement 使用官方注册 entry 的 renderer/store 声明适配 rc.2；维持官方文件生命周期与单标签栏，并扩展上下拆分、最多四格、琉璃标签跨外层卡片投放。实际验证开发者工具标签拖到会话区下方形成上下拆分。
- header 卡片与外层浮动面板材质改为本体绘制，避免负层级伪元素采样失败；普通面板使用用户的正常模糊值，关闭材质同时清零强模糊变量。已实测 40%→100%→40% header 响应，恢复用户原值。
- 壁纸预览空白源于通用 _preview 规则把图片背景替换为噪声；专用预览容器已从该规则中排除，实际设置页恢复显示壁纸与裁切框。
- GIF、动态 WebP、APNG 按容器块检测，保留原始数据而非 JPEG 转码；单文件最大 32MB，较大数据以 IndexedDB 保存。预览订阅壁纸快照，补充解码错误提示。已通过三格式识别与截断输入测试；尚未逐格式进行动画播放及大文件重启的视觉验收。

## rc.17 菜单与侧栏位置

- 常驻“应用 / 编辑”维持在桌面窗口左上角的 body 层，侧栏收起、浮动与换边都不会移动它；左缘侧栏只为这个入口留出顶部空间。保留侧栏原有 DeepSeek Logo、品牌名和旁边的展开/收起按钮。
- Dockable 模式下右侧栏开关注册在官方 `conversation.session.header.corner` 单席位，恢复原本的右上角位置并持续可见；官方右栏自带的展开与收起按钮继续隐藏，分栏按钮仍隐藏。已在真实桌面窗口核对 Logo、两处开关和常驻菜单，左侧收起后菜单仍保留。
- 右栏卡片直接绘制琉璃材质与边框，去掉 dockkit 标签层的不透明底；PDF 预览背景也设为透明，实际 PDF 页面仍由原预览器绘制。当前验证用的 PDF 已不存在，因此只能核对缺失文件状态的外观，未测试真实 PDF 页面的阅读效果。

## rc.18 传统标题栏模式

- 功能设置的“窗口顶栏”提供“悬浮控件（无标题栏）”与“传统标题栏（常驻）”，说明写明两种模式的窗口控件行为。
- 传统模式在官方无边框主窗口内加入 40px 横贯顶栏作为拖窗区域；原生应用/编辑菜单在左，琉璃的最小化、最大化与关闭按钮在右，持续可见。dock 画布高度减去 40px、下移 40px；设置遮罩从顶栏下方开始。
- 悬浮模式保留原来的角落提示与智能避让。切换模式时，WindowControls 监听设置对应的 html 属性并更新隐藏状态。
- 已在真实官方桌面端切换到传统模式并核对：菜单和三个窗口按钮可见、卡片位于顶栏下方、设置对话框未被顶栏遮挡。浮动模式回切代码已通过构建，尚未完成独立的实际 UI 回切验收。

## rc.20 右栏 Dockable 回归

- 官方桌面端在“琉璃 Dockable”设置下重新以 LiuliDockSurface 渲染可见右栏，恢复四向落区、跨外层卡片投放、琉璃 tab chip 样式及 details 卡片的 edge-bottom 触底去圆角。此前对官方 RightbarSeat/DockLayout 的包装适配已移除。
- 原生 RightbarSeat 仍挂载以维护官方文件资源的会话与 Tab 生命周期，选中“官方文件与预览”时只投影正文。原生第二条 tab strip 在该投影下隐藏；官方文件条目通过同一条可见琉璃标签栏末端的标题按钮切换。
- 设置切到“官方侧边栏”时使用官方原生右栏，不再额外修改它的 DockLayout 规则。
- 已通过完整 TypeScript 构建和本地包打包。用户选择自行进行真实 UI 验收；本版本安装后需重启官方客户端加载新插件。

## rc.21 空右栏的幽灵标签

右栏停留在“打开标签页”空状态时，官方 Tab 域仍可能保留此前的 PDF 与“文件”页面。rc.20 的 OfficialResourceTabs 无条件读取 `tabsIn(sessionId)`，把这两项画在琉璃 dock 的顶端，造成空状态上方出现无法解释的两个标签。rc.21 改为只在琉璃 `official` 卡片被选中时渲染官方资源切换器；其余面板和空状态都不显示这些历史资源入口。原生资源记录及文件预览功能不受此展示条件影响。

## rc.22 官方文件入口

旧的“官方文件与预览”入口每次都调用 `sidebarRight.openTab('guide')`，因此即便之前已打开 PDF，也会新增官方“开始”页。现在统一复用当前真实文件标签；如果当前停在引导页或“文件”页且有既存文档，则优先聚焦最近的文档。只有该会话的官方 Tab 域为空时，才打开引导页。卡片点击、右键菜单和程序导航共用这条规则。

## rc.23 优先复用官方功能

- 官方 Windows 桌面端的浏览器、终端和文件树入口调用 `ctx.sidebarRight.openTab`，使用官方 Browser WebContentsView、WebTerminal 和 Files 页；有路径的代码/文档预览通过官方 `dsh-resource://file/session/...` 地址调用 `openResource`。社区客户端保留原琉璃实现。
- 已保存在琉璃 dock 中的旧浏览器、终端、文件树标签，在用户重新选中时迁移到官方标签并关闭旧标签，避免继续使用受限制的 iframe 或失联的 WebSocket 输入。空右栏投影官方引导页，点击官方入口时才生成相应卡片；引导页本身不会额外创建琉璃标签。
- 历史会话中 `D:\Xpin\交付\试稿说明_机器人动态平衡.{pdf,html}` 两个文件已不在磁盘上。官方预览对此提示“文件不存在”是准确的；当前交付目录另有 `v10_制作思路与交付说明.pdf`，此版本不自动把旧文件引用改指到新内容。
- 文件地址编码与官方 `sessionFileAddress` 对相对路径、Windows 绝对路径和保留字符进行逐项对照，结果一致；已通过完整 TypeScript 构建。浏览器访问和终端输入由用户在官方桌面窗口验收。

## rc.24 右栏与菜单修正

- 右栏已有官方文件时不再新开“开始”页；文件标签优先展示真实资源。官方文件导航直接展开琉璃侧栏，避免隐藏的原生 Seat 状态让预览请求失效。
- 官方开始页投影到琉璃卡片时使用壁纸材质与主题色 Material 图标，保留官方入口和快捷键。
- 琉璃会话右键菜单接入官方置顶、重命名、分叉、归档和恢复；活动会话归档时提供显式确认。对话文件文字、文件卡片与官方“显示文件位置”入口接入琉璃文件菜单和定位链路。
- 主区域按官方 `activePanelId` 切换页面，修复侧栏“插件”入口；显示全局页时收起独立会话页头卡片。
- 顶部额度根据会话页头卡片实际宽度收缩：先隐藏进度条保留额度文字，进一步变窄时隐藏整组额度。
- rc.24 已通过 TypeScript 检查与完整构建，安装到官方桌面 profile；界面交互留待重启后验收。

## rc.25 插件页、官方标签与动态壁纸

- 官方插件页加入高对比琉璃阅读底，列表扩展到 1480px 并在足够宽时排为两列；卡片与详情页文字、间距和信息层级调整为紧凑布局。官方及第三方插件图标换成按功能区分的主题色 Material 符号，保留官方按钮、开关和详情页流程。
- 官方每个文件或工具标签按原生 tab id 映射成独立琉璃标签，去掉右上角第二排资源小标签；琉璃标签的选择和关闭同步原生控制器，关闭最后一个后展示官方开始页。原生 Seat 同一时刻只渲染一个非浏览器正文，因此拆成多格后仅当前文件显示正文，其余文件卡可点击切换。
- 进入插件或计划任务等全局页时自动收起右栏，返回同一会话后恢复先前开合状态；新建空白会话也收起旧右栏。
- 动态 WebP 在上传时保留原容器字节；Host 的设置请求专用上限提高到 48 MiB，覆盖 32 MiB 原文件的 Base64 体积。官方端上传会等待 Host 写入并在失败时提示，启动恢复加防旧响应覆盖新壁纸的时序检查。
- 本机旧版 Host 记录里目前保存的是 JPEG；已经被旧版覆盖的 WebP 动画无法从该记录反向恢复，需在重启加载 rc.25 后重新上传原始动态文件一次。
- 源码审计后补齐计划任务页、修改文件卡、问答记录卡、工作流标题、官方文件树/文本预览的局部材质，并统一官方菜单材质令牌。PDF 页面、终端画布、浏览器网页继续使用适合内容的背景。
